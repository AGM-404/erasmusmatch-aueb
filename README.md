# ErasmusMatch AUEB

A mobile-first React + Vite mockup for exploring AUEB Erasmus partnerships and preparing a student profile. The interface deliberately separates confirmed partnership records from demonstration destinations and does not present unverified course matches as academic recommendations.

## Run locally

```sh
npm install
npm run dev
```

Run automated checks with `npm test`, `npm run lint` and `npm run build`.

## What the mockup does

- **Explore** displays six featured official partnerships: Ghent University, Comenius University in Bratislava, Matej Bel University in Banska Bystrica, Sofia University St. Kliment Ohridski, WU Vienna University of Economics and Business, and the University of Latvia. The first four are core features; WU Vienna and Latvia are additional candidates with incomplete course verification. All 46 individual AUEB partnership records remain intact in the source dataset. Add an Erasmus code and display label to `featuredPartnerConfig` in `src/data/featuredPartners.js` to expand the visible partner list.
- **Profile** bundles 94 official AUEB Marketing & Communication course listings from [the department catalog](https://www.dept.aueb.gr/el/mbc_courses) and their linked course pages. Students can filter by semesters 1–8, search titles, review semester 7–8 specialization/elective categories, and select any courses they have not passed or wish to seek recognition for. Selections persist in browser storage. Each AUEB course is 5 ECTS. Official course codes, descriptions and learning outcomes are included when published; absent information remains empty, and syllabus links remain unavailable. Course descriptions and outcomes can be reviewed from each course listing. Courses marked “Not offered in 2026–2027” remain visible with an explicit warning.
- **Matches** shows an evidence-gated Academic Match indicator for each of the six featured real partners. A percentage appears only when selected AUEB and host courses have verified course text, relevant title/topic and description/syllabus/outcome evidence, strict host metadata, a complete term catalog, and compatible documented teaching language. A topic-only overlap remains an unverified possibility, not an equivalency; insufficient evidence is labeled explicitly rather than scored.
- Recommendation explanations show potential course pairings, the shared title/content evidence, ECTS, term, language, eligibility, verification status, and missing evidence. A potential pairing is never an academic approval.
- The ECTS checker independently counts explicitly verified host-university ECTS and explicitly verified AUEB-recognized ECTS against separate 30-ECTS targets. Unknown or unverified credits never count. These targets are planning checks requested for the mockup, not a claim that the loaded data verifies a student's eligibility.
- **Official course data updates** accepts validated JSON/CSV files or JSON from the configured backend/API endpoint `VITE_COURSE_DATA_API_URL`. Configure it in the Vite environment before building; the endpoint must return JSON. The app has no user-entered arbitrary fetch URL and does not scrape university websites. Records carry partner, academic year, semester, course code/title, ECTS, language, study level/Bachelor eligibility, catalog and syllabus URLs, last-checked time, and status (`current_verified`, `historical`, `unverified_candidate`).
- A record marked `current_verified` must include positive ECTS, language, explicit Bachelor eligibility separate from exchange eligibility, HTTPS catalog and syllabus URLs, and an ISO source-checked timestamp. Current verified and unverified-candidate listings can be selected for provisional planning; historical listings remain unavailable. This is schema/provenance validation, not independent verification that a source is official; that responsibility stays with the data provider/coordinator. Imported records persist in the current browser's local storage and remain separate from demo destinations.
- **Provisional Learning Agreement planning** allows verified and unverified candidate listings for the selected real partner and academic year. In Matches, students can pair each selected host course with one or more Profile AUEB courses, and an AUEB course can be paired with multiple host courses. Pairing totals count each course once; host and AUEB ECTS are separate and need not match. Each pairing remains Pending Academic Approval. Automated suggestions are unavailable unless verified course descriptions and syllabi are supplied; title-only similarity is never scored.
- The generated coordinator email includes every proposed pairing, the separate ECTS values, available host and AUEB syllabus links, official AUEB course-page links, and the Pending Academic Approval status. AUEB syllabus, code and description details are not invented when unavailable.
- Official Learning Agreement readiness is separate from provisional planning: strict current host-course checks and both 30-ECTS requirements must be met by verified host and AUEB-recognized credits. Selected AUEB course listings and student-proposed equivalencies do not count as verified recognition, and readiness never implies coordinator approval.
- The generated Greek email is an editable review draft and can be created when credits are missing, unresolved, or below 30 ECTS. It lists the provisional totals and unresolved issues for coordinator confirmation. A coordinator address is used only when supplied in Profile; without one, the draft can be copied without an invented recipient. With an address, it opens only in the user's email application via `mailto` and is never sent automatically. Oversized mailto URLs offer a copy-to-clipboard fallback.
- Approval request states (`Draft`, `Awaiting Review`, `Approved`, `Changes Requested`, `Rejected`) are manually controlled and persisted in local storage. Opening an email draft does not advance the state. Browser-local status is not confirmation from AUEB.
- Approval draft text, status records and selected AUEB course IDs are stored in the browser's local storage. Approval drafts may contain personal data; other Profile fields remain in the current page session.

## Data and limitations

- `ErasmusMatch_Copilot_Data/data/raw/partner_universities_2026_27.json` is joined with `ErasmusMatch_Copilot_Data/data/catalogs/catalog_master.csv` by source partner ID in `src/data/erasmusPartners.js`. Duplicate university names remain separate partnership records and study cycles.
- The bundled partnership source marks term-wide catalog completeness as unverified. Of the 139 bundled host-course records, 28 Ghent and 15 Comenius listings have current course verification; 96 remain candidates. All 51 Comenius candidates appear on the Faculty of Management's 2026–2027 incoming course lists, where current ECTS, semester and Bachelor level are published. Exact-identity Comenius information sheets supplied syllabus text and learning outcomes for 39 records; prior-year sheets, missing academic-year details and official course-code conflicts remain explicitly unverified. These partial listings do not establish complete catalog coverage or AUEB recognition, and actual course schedules may change. Imported records can carry `description`, `syllabus_text` and `learning_outcomes`; these are used only when supplied in records that also satisfy strict verification and catalog-completeness checks.
- Explore and Matches use the same configured featured-partner list. Course records for other partners may remain in imported browser data but are not shown in these featured-partner screens. Current verified listings, historical listings and unverified candidates retain separate labels; a partial set of current listings is not represented as a complete catalog.
- `src/utils/recommendationEngine.js` uses only evidence-gated academic course matching. No course similarity or equivalency is inferred from titles alone.
- `src/utils/ectsValidator.js` counts only unique courses with an explicit `verified: true` flag and numeric ECTS. It reports the host and AUEB sides independently and returns a confirmation-required state when evidence is incomplete.
- `src/data/auebCourseCatalog.json` contains the official AUEB listings, category membership, source links and explicit 2026–2027 availability notices. Unknown AUEB metadata remains null and unverified. `src/utils/auebCourseCatalog.js` handles semester filtering, course grouping and browser-persisted selections; `src/utils/approvalRequest.js` handles course pairings, de-duplicated ECTS totals, email generation and strict official-readiness checks.
- `tests/recommendationEngine.test.js`, `tests/featuredPartners.test.js` and `tests/ectsValidator.test.js` cover profile-driven ranking, the six featured partners and configurable expansion, preservation of all 46 records, unknown language/catalog data, non-invention of equivalencies, independent ECTS thresholds and incomplete records.
- `tests/courseData.test.js`, `tests/auebCourseCatalog.test.js` and `tests/approvalRequest.test.js` cover host/AUEB catalog import provenance, provisional selection, many-to-many course pairings, unique-course ECTS totals, full email pairings and syllabus links, strict approval readiness, recipient configuration and long-mailto fallback.

No course names, ECTS values, course equivalencies, term availability or success percentages should be treated as official unless verified against current AUEB and host-university sources.
